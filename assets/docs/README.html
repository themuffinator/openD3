DOOM 3 ON A MODERN OPEN-SOURCE ENGINE

openD3 replaces Doom 3's engine and game binaries with its own, built from id Software's GPL source on top of the openQ4 engine. The campaign and multiplayer maps load from your retail game files, with openQ4's window handling and a choice of OpenGL or Vulkan rendering.

openD3 does not include any Doom 3 game data. You need your own copy of Doom 3 (2004); Doom 3: BFG Edition's data is a different format and is not supported.

EARLY DEVELOPMENT

openD3 has no release yet. It has just moved onto the current openQ4 engine, and so far only the first campaign map and a dedicated-server start have been run on it. The release status and the rebase record say exactly what has been run.

Highlights

What has been run so far, on Windows x64 against the Steam release of Doom 3:

Game files
Startup locates the install, verifies pak000–pak004 by checksum and ignores the retail game binaries.
Campaign
game/mars_city1 loads, plays its opening cinematic with working in-world screens, and autosaves.
Renderers
The same map renders on the default OpenGL renderer and on the native Vulkan renderer (+set r_renderApi vulkan).
Interface
Doom 3's original main menu starts and plays the intro video, and both consoles carry Doom 3's colours.
Server
openD3-ded_x64 starts a deathmatch map; see the server setup guide.

Not yet checked: playing beyond the first cinematic, loading saves, level changes, a client joining a multiplayer server, Resurrection of Evil maps, and every platform other than Windows x64.

Getting Started

  1. Install Doom 3. Leave it where it is; openD3 keeps to its own folder.
  2. Build and stage openD3 with BUILDING.md. The staged package lands in .install/.
  3. Launch openD3-client_x64 from .install/. openD3 finds your Doom 3 install on its own; if it does not, add +set fs_basepath "path\to\Doom 3".
  4. Never copy retail .pk4 files into baseod3/. That folder is for openD3's own files.

Getting Started covers requirements, updating and where your files go.

Compatibility and Scope

  • openD3 runs the official retail Doom 3 assets with its own engine and game modules. The retail gamex86 binaries are never loaded, so mods that ship their own game DLL for that interface do not work.
  • Content-only mods need a mod.json; see the technical reference.
  • Resurrection of Evil's game module loads with +set fs_game d3xp, but no expansion map has been run. See Campaigns.
  • Retail Doom 3 clients and servers are not expected to join openD3 games, or the other way round. Use matching openD3 builds everywhere.
  • Only Windows x64 has been built and run. The openQ4 engine underneath also supports Linux, Steam Deck, macOS and Android, but openD3 has not been tried on any of them.

Building from Source

openD3 builds with Meson and Ninja, with dependencies fetched as Meson subprojects. On Windows, run Meson through tools/build/meson_setup.ps1:

  1. Configure: meson_setup.ps1 setup builddir . --backend ninja --buildtype=debugoptimized --wrap-mode=forcefallback
  2. Compile: meson_setup.ps1 compile -C builddir
  3. Stage: meson_setup.ps1 install -C builddir --no-rebuild --skip-subprojects

BUILDING.md has the prerequisites, options and output layout.
