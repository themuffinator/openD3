# Building openD3

openD3 builds with [Meson](https://mesonbuild.com/) and Ninja. Dependencies come
from Meson subprojects, fetched at configure time.

Only the Windows x64 build has been exercised for openD3 so far. The Linux,
macOS and Android instructions that applied to the openQ4 engine are expected to
carry over, but they have not been tried here; see the
[rebase record](docs/dev/doom3-rebase.md).

## Requirements

| | |
|---|---|
| Compiler | MSVC 19.46 or newer (Visual Studio 2022 17.14+ or 2026) with the x64 C++ tools |
| Meson | 1.6.0 or newer |
| Ninja | any recent release |
| Python | 3.11 or newer, with Pillow for the icon sync step |
| OpenAL Soft runtime | `OpenAL32.dll` for x64, see below |

The engine is C++20; the game modules build as C++17.

### OpenAL runtime on Windows

Staging copies an OpenAL Soft `OpenAL32.dll` next to the executables. The DLL is
not tracked in Git. Provide one of:

- the file at `src/external/openal-soft/bin/win64/OpenAL32.dll`, or
- `OPEND3_OPENAL_ROOT` set to a folder that contains `bin/OpenAL32.dll`.

`tools/build/prepare_windows_openal.ps1` can build a package to point
`OPEND3_OPENAL_ROOT` at.

## Windows

Always run Meson through `tools/build/meson_setup.ps1` rather than calling
`meson` from an arbitrary shell. The wrapper puts the MSVC tools on `PATH` and
syncs the icon set first. `tools/build/opend3_devcmd.cmd` opens a prompt with
the same environment.

```powershell
# Configure
powershell -ExecutionPolicy Bypass -File tools/build/meson_setup.ps1 setup builddir . --backend ninja --buildtype=debugoptimized --wrap-mode=forcefallback

# Compile
powershell -ExecutionPolicy Bypass -File tools/build/meson_setup.ps1 compile -C builddir

# Stage the runtime package into .install/
powershell -ExecutionPolicy Bypass -File tools/build/meson_setup.ps1 install -C builddir --no-rebuild --skip-subprojects
```

Use `--buildtype=debug` or `--buildtype=release` as needed. `--skip-subprojects`
keeps third-party installs out of the package tree.

The generated version header carries the Git commit, so the first compile after
a new commit rebuilds most of the tree.

## What the build produces

In `builddir/`, and staged into `.install/`:

| File | What it is |
|---|---|
| `openD3-client_x64.exe` | The game client |
| `openD3-ded_x64.exe` | The dedicated server |
| `renderer-gl_x64.dll` | OpenGL renderer module |
| `renderer-vk_x64.dll` | Vulkan renderer module |
| `baseod3/game_x64.dll` | Doom 3 game module, from `src/game` |
| `baseod3/game-d3xp_x64.dll` | Resurrection of Evil game module, from `src/d3xp` |
| `baseod3/pak0.pk4` | openD3's runtime content, packed from `content/baseod3/pak0` |
| `baseod3/mod.json` | The runtime directory's manifest |

`.install/` is the package root to run from. `builddir/` holds the same binaries
plus compiler and linker intermediates.

## Useful options

Pass with `-D<name>=<value>` at configure time.

| Option | Default | Effect |
|---|---|---|
| `build_engine` | `true` | Build the client, dedicated server and renderer modules |
| `build_games` | `true` | Build the game modules |
| `build_game_d3xp` | `true` | Build the Resurrection of Evil module |
| `build_renderer_vk` | `true` | Build the Vulkan renderer module |
| `use_pch` | `true` | Use precompiled headers |
| `platform_backend` | `sdl3` | Window and input backend |

`meson_options.txt` lists the rest, most of them inherited from openQ4.

## Running

```powershell
.install\openD3-client_x64.exe +set r_fullscreen 0 +set ui_retained 0 +set logFile 2 +set logFileName logs/opend3.log
```

- The engine finds Doom 3 through Steam, GOG, the registry and known folders.
  Otherwise add `+set fs_basepath "<Doom 3 folder>"`, or set `OPEND3_DOOM3_PATH`.
- `+set r_renderApi vulkan` selects the Vulkan renderer.
- `+set fs_savepath <folder>` redirects saves, config and logs, which is how to
  keep a test run from touching your normal profile.
- `+map game/mars_city1` starts a map directly.

The VS Code launch configurations in `.vscode/launch.json` cover the campaign
and multiplayer maps on both renderers. They are generated by
`tools/debug/generate_vscode_launch.py`.

## Regenerating the Vulkan shader headers

The Vulkan module embeds SPIR-V from committed headers, so a normal build needs
no shader compiler. After changing a shader under `src/renderer/Vulkan/shaders`,
regenerate the headers with `tools/build/spirv_to_header.py`; with
`glslangValidator` on `PATH`, `python tools/tests/vk_shader_header_pin.py`
checks them and prints the exact command for a stale one.
